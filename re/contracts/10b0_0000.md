# 10b0:0000 inferred_draw_bitmap_clipped
Status: understood · Cluster: graphics and sprites · Convention: cdecl far, 16 words of arguments, caller cleans

**Purpose (confirmed):** Draw a rectangle of an 8-bit picture into the 8-bit off-screen buffer, clipped to the buffer, choosing the right drawing routine (confirmed).
**Inputs:** Words from `[bp+6]`: destination bitmap header far pointer (offset, selector; width at +4, height at +8, bit count at +0xe); destination pixels far pointer (offset at `[bp+a]`, selector at `[bp+c]`); x and y of the rectangle's top-left in the destination; source pixels far pointer; source bitmap header far pointer (`biCompression` at +0x10 decides the format); source x and y offsets; rectangle width and height; keyed flag; key colour byte.
**Outputs / state written:** Clips the rectangle to the destination with `IntersectRect`; if nothing is left it returns 0, otherwise 1. A negative destination height means a top-down buffer (direction flag -1); the usual positive height is a bottom-up buffer. Row stride is `((width * bitCount + 31) & ~31) / 8`, four-byte aligned, for both source (plain pictures) and destination. The source start is found from the bottom of the clipped rectangle, because BMP rows are stored bottom first: `(sourceHeight - (topClip + rows) - sourceY) * stride + leftClip + sourceX`. For span pictures (`biCompression` = 2) the rows above are skipped by walking the span records (`4 + length` bytes each) instead. Dispatch: span picture, keyed or not: `inferred_blit_spans_keyed`; plain picture and keyed: `inferred_blit_rows_keyed`; plain and not keyed: `inferred_blit_rows_copy`.
**Calls:** `IntersectRect`, `10d0:052a` (32-bit multiply), `10b8:0254`, `10b8:0024`, `10b8:0104`.
**Yields / blocks / timing:** none
**Edge cases:** Spans are always drawn with the key colour skipped, whatever the keyed flag says. The row-stride mask `0xffe7` is equivalent to the usual `& ~31` once shifted right by 3. The top-down branch is only partly followed (the game's buffer is bottom-up). Callers always pass key colour 0, so palette entry 0 is the transparent colour.
**Evidence:** `re/export/fn/10b0_0000.asm`, read instruction by instruction, and the three callers' stack layouts (`1078:1aea`, `1078:1b6c`, `1080:0d56`).
