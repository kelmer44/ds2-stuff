# 1078:0a00 inferred_erase_sprite_rect
Status: understood · Cluster: graphics and sprites · Convention: cdecl far, caller cleans

**Purpose (confirmed):** Repaint the area where a sprite used to be, after it was removed (confirmed).
**Inputs:** `[bp+6..8]` scene far pointer, `[bp+a]` dc, `[bp+c..e]` sprite far pointer, `[bp+10]` depth threshold.
**Outputs / state written:** Removes the sprite from list 0 (`inferred_remove_sprite`); takes its old rectangle (x +0x22, y +0x24, width +0x26, height +0x28), clipped on all four sides to the scene's clip rectangle (+0x34a left, +0x34e top, +0x34c right, +0x350 bottom); if both sizes are positive, composes it with the same steps as `inferred_redraw_rect` (backdrop, sprite list with the given threshold, debug text, stretch blit).
**Calls:** `1078:0806`, `1078:0172`, `1078:1aea`, `1078:06f4`, `1078:0000`.
**Yields / blocks / timing:** none
**Edge cases:** The old width and height come from the sprite record, so a sprite whose old size was stored wrongly (see `inferred_update_sprite_in_rect`) is erased with that size. The decompiler shows the dc handle where a width belongs in two calls; the assembly (`PatBlt` and `WinGStretchBlt` argument pushes) uses the clipped width and height correctly.
