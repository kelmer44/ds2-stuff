# 1048:0b54 inferred_next_room_token
Status: understood · Cluster: script and rooms · Convention: cdecl far, caller cleans

**Purpose (confirmed):** Read the next line of a room (`ROOMnnnn.DAT`) script file and return its keyword code (confirmed).
**Inputs:** `[bp+6]` near pointer to a buffer that receives the value text.
**Outputs / state written:** Reads one line from the loaded file buffer (far pointer `DS:3416/3418`, read position `DS:16f4/16f6`, end `DS:341a/341c`) up to and including the newline. A line of two characters (just CR LF) returns 0. Otherwise it cuts the line at the first `;` (a comment) and drops trailing spaces, skips leading spaces, splits at the first `=`: the part up to and including `=` is the key, the rest is the value text. The key is upper-cased (`1060:0000`) and compared with the keyword table; the matching code is returned, 0 when the key is not in the table (so any unknown key or a line without `=` is silently ignored by the callers). The table has 51 keywords, listed in `SCRIPT_LANGUAGE.md`; `ENDID=` returns 99 and `CLIPXY=` returns 0x3e. The counter `DS:16f8` is incremented on every keyed line; the `COND=` check of the object lexer is not done here.
**Calls:** `1060:0000`, `lstrcpy`, `lstrcmp`.
**Yields / blocks / timing:** none
**Edge cases:** Same limits as `inferred_next_obj_token`. Both lexers use the same line splitting, so a key is never case sensitive.
**Evidence:** `re/export/fn/1048_0b54.c`; keywords checked against all 167 files (every key used in the data is in the table except the single `Chnage=`).
