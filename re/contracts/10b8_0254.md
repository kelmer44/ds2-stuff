# 10b8:0254 inferred_blit_rows_copy
Status: understood · Cluster: 32-bit bitmap helpers · Convention: pascal-style far, callee pops 0x1a bytes; 32-bit code in a 16-bit segment

**Purpose (confirmed):** Copy a block of 8-bit pixels row by row from source to destination (confirmed).
**Inputs:** Stack, from `[bp+6]`: dword source row stride, dword destination row stride, dword row count, dword row width in bytes, source far pointer (offset word, selector word), dword destination offset, destination selector word.
**Outputs / state written:** For each row copies `width` bytes (`rep movsd` then `rep movsb`), then adds the row gaps (stride minus width). Does nothing when width or row count is 0.
**Calls:** none (DPMI descriptor fix-up at first call, see edge cases).
**Yields / blocks / timing:** none
**Edge cases:** Each routine in segment `10b8` starts with a one-time stub: it adds 0x8000 to itself to test a carry flag that is set only on the first call, and the stub then uses DPMI (`int 31h`, functions 000Bh and 000Ch) to set the 32-bit default bit in the code segment's descriptor. Ghidra decodes the stub bytes as a `mov eax` and does not show the `int 31h`. No clipping and no transparency.
