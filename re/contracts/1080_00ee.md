# 1080:00ee inferred_set_windows_palette
Status: understood · Cluster: graphics and palette · Convention: cdecl far (dc, far pointer to 256 colour entries)

**Purpose (confirmed):** Turn 256 colour entries stored as blue, green, red, unused bytes into a Windows logical palette, select it into a device context and realize it (confirmed).
**Inputs:** `[bp+6]` device context, `[bp+8..a]` far pointer to 256 four-byte entries (B, G, R, unused), the layout of a `.pal` file and of a BMP colour table.
**Outputs / state written:** Allocates a 0x408-byte block (palette version 0x300, 256 entries), copies every entry as R = src[2], G = src[1], B = src[0], flags 0. Stores the new palette handle in `DS:200a` WITHOUT freeing the previous one, selects it (`SelectPalette(dc, pal, FALSE)`), realizes it, frees the block, returns the handle. Errors shown: "set_windows_palette: Unable to allocate local memory" and "Unable to create palette".
**Calls:** `LocalAlloc`, `LocalLock`, `CreatePalette`, `SelectPalette`, `RealizePalette`, `LocalUnlock`, `LocalFree`, `1098:0000` error report.
**Yields / blocks / timing:** none
**Edge cases:** Every entry is copied, including entry 0 and entry 255, so there is no reserved black or white here, unlike `inferred_make_bmp_palette`. The old palette object leaks when this is called twice.
**Evidence:** `re/export/fn/1080_00ee.c` and `.asm`; caller `1080:0650`.
