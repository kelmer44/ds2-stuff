# 10b8:0104 inferred_blit_spans_keyed
Status: understood · Cluster: 32-bit bitmap helpers · Convention: pascal-style far, callee pops 0x1c bytes; 32-bit code

**Purpose (confirmed):** Draw a picture stored as one span per row (skip, length, pixels), skipping key-colour pixels inside each span (confirmed).
**Inputs:** Same stack layout as `inferred_blit_rows_keyed`; the source points at the first row's span record.
**Outputs / state written:** Per row: reads word `skip` and word `length` from the source; the leading `skip` pixels are left alone (the destination moves on), then `length` pixels are copied except those equal to the key colour; the source advances by `4 + length` and the destination by the row gap. A row whose skip is smaller than the left clip is trimmed from the span, and a span longer than the clip width is shortened. Rows with nothing left to draw are skipped.
**Calls:** none (same one-time DPMI stub).
**Yields / blocks / timing:** none
**Edge cases:** The span format is the one used by BMP files whose `biCompression` is 2 (see `STRUCTS.md`); it is not Windows RLE. A BMP of this kind can only be drawn by this routine, not by Windows. `length` can be 0 for an empty row.
**Evidence:** `re/tools/ne_segments.py dis 10b8:0104 0x130 --use32`; sample file `204SMK20.BMP` decoded in Python as skip 0, length 8 for each row.
