# 1080:0be0 inferred_make_bitmap_rgb
Status: understood · Cluster: graphics and palette · Convention: cdecl far (dc, image record near pointer)

**Purpose (confirmed):** Create a Windows bitmap (device-dependent) from an image record's BMP data using the game palette (confirmed).
**Inputs:** `[bp+6]` device context, `[bp+8]` near pointer of the image record (data pointer at +2/+4).
**Outputs / state written:** Selects the game palette `DS:200a` into the dc, and when the record has data: saves width and height into the record, saves the BMP's four header words at 0x26 and 0x28 into the record (+0xc, +0xe) and clears them, then `CreateDIBitmap(dc, header, CBM_INIT, bits, info, DIB_RGB_COLORS)` and stores the handle at +0. Restores the palette selection. Returns whether the record had data; with no data it reports "process_image: NULL pointer assignment".
**Calls:** `SelectPalette`, `CreateDIBitmap`, `1098:0000`.
**Yields / blocks / timing:** none
**Edge cases:** Only the first two of the four header words are saved here (the other path, `inferred_read_image_header`, saves all four). The bits pointer is the file start plus the offset in the BMP file header (`bfOffBits`). Compression 2 sprites (row spans) are not valid input for Windows bitmap creation; this path is for uncompressed pictures.
**Evidence:** `re/export/fn/1080_0be0.c`; two direct callers.
