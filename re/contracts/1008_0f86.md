# 1008:0f86 inferred_build_dim_remap
Status: understood · Cluster: main window and input · Convention: cdecl far, no arguments

**Purpose (inferred):** Build a 256-entry table that maps every colour of the current 256-colour palette to the closest colour of the same palette after the colour is darkened and shifted; used to dim a picture drawn behind a dialog.
**Inputs:** The palette copy at `DS:9798`: 256 entries of 4 bytes (three colour bytes and one flag byte, Windows colour-table order). Reads nothing else.
**Outputs / state written:** Fills the byte table `DS:93b4` (256 bytes): entry *i* is the palette index nearest to the shifted colour of entry *i*. For each entry the three bytes are changed first: byte 0 becomes `byte0 * 256 / 384` (two thirds), byte 1 becomes `(byte1 - 64) * 256 / 384`, byte 2 becomes `byte2 * 256 / 512` (half); each result is clamped to 0..255. Then every palette entry *j* is tried: it is a candidate only if the byte 0 and byte 1 differences are each smaller than the best distance so far; the distance is the largest of the three absolute differences (byte 2 is compared against its shifted value too). The first candidate with the smallest distance wins; the starting best distance is 256, so a table entry is always set. The table starts as the identity.
**Calls:** `10d0:0490` (32-bit divide, used for the three scalings), the stack-check helper `10d0:029e`.
**Yields / blocks / timing:** none. About 65,000 inner steps, so it is run once per dialog opening.
**Edge cases:** Byte 1 below 64 gives a negative value that is clamped to 0. Ties keep the lowest index. The flag byte is not used.
**Evidence:** `re/export/fn/1008_0f86.c` and `.asm` (the three `CALLF 10d0:0490` with divisors 0x180, 0x180, 0x200, the clamps, the `abs` chain and the stores at `DS:93b4`); callers `DIALOGPROC` (`1068:09a0`) and `1008:0af6`, which both then read the table at `1068:0a36` and `1008:0ce9` while copying a 520-pixel-wide image row by row.
