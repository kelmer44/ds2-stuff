# 1048:0000 inferred_next_obj_token
Status: understood · Cluster: script and rooms · Convention: cdecl far, caller cleans

**Purpose (confirmed):** Read the next line of an object (`OBJ_nnnn.DAT`) script file and return its keyword code (confirmed).
**Inputs:** `[bp+6]` near pointer to a buffer that receives the value text (the part after `=`).
**Outputs / state written:** Reads one line from the loaded file buffer (far pointer `DS:3416/3418`, read position `DS:16f4/16f6`, end `DS:341a/341c`) up to and including the newline. A line of two characters (just CR LF) returns 0. Otherwise it cuts the line at the first `;` (a comment) and drops trailing spaces, skips leading spaces, splits at the first `=`: the part up to and including `=` is the key, the rest is the value text. The key is upper-cased (`1060:0000`) and compared with the keyword table; the matching code is returned, 0 when the key is not in the table (so any unknown key or a line without `=` is silently ignored by the callers). The table has 25 keywords (codes in `SCRIPT_LANGUAGE.md`). `COND=` returns 1: if no other keyed line was read since the previous `COND=` (counter `DS:16f8` is 0) it first shows the message box "No Info for this Condition!"; the counter is reset on each `COND=` and incremented on every other line.
**Calls:** `1060:0000` (upper-case), `lstrcpy`, `lstrcmp`, `1098:0248` (message box).
**Yields / blocks / timing:** none
**Edge cases:** Lines longer than about 500 characters overflow the stack buffer. A file without a trailing newline would read past its end (the end position is only checked by `inferred_skip_line`). The keys are compared exactly after upper-casing, so a misspelling such as `Chnage=` returns 0 and the line has no effect (it occurs once, in `OBJ_0307.DAT`).
**Evidence:** `re/export/fn/1048_0000.c`; the 25 keyword strings and codes extracted from the code and checked against all 167 object and room files of the game.
