# 1078:05be inferred_sort_sprite_list
Status: understood · Cluster: graphics and sprites · Convention: cdecl far, caller cleans

**Purpose (confirmed):** Remove empty slots from a sprite list and sort it by depth (confirmed).
**Inputs:** `[bp+6..8]` far pointer to the first list entry, `[bp+a..c]` pointer to the list's entry count.
**Outputs / state written:** Packs the non-null far pointers to the front of the list and updates the count (a null entry before the end is overwritten by the next non-null one). Then a selection sort orders the sprites by their anchor y (sprite +0x30), ascending: smallest y first. Equal values keep the first minimum found; the algorithm swaps, so ties are not guaranteed to keep their order.
**Calls:** none.
**Yields / blocks / timing:** none
**Edge cases:** Entries are far pointers of 4 bytes; the sort looks only at +0x30. This is the draw order: farther (smaller y) first, nearer last.
