# 1040:011a inferred_find_walk_path
Status: understood · Cluster: walking · Convention: cdecl far, caller cleans (5 words)

**Purpose (confirmed):** Find a walkable path between two grid cells and store it, as a short list of corner cells, for the game tick to follow.
**Inputs:** `[bp+6]` window handle; `[bp+8]` start column and `[bp+a]` start row; `[bp+c]` goal column and `[bp+e]` goal row. Columns are grid columns of the 80 by 48 grid (map column + 8), rows are 0 to 47. The caller `1010:07c6` passes the player's cell and the clicked cell.
**Outputs / state written:** Working grid `DS:3eba` (80 x 48 words). On success the path list `DS:3cb2` and its last index `DS:097c`: entry 0 is the goal cell, then the corner cells found while walking back, last the start cell; each entry is `row * 80 + column`. Then posts message 0xf (WM_PAINT) to the window. On failure nothing is written.
**Calls:** `1060:0b00` (reads `SysMapBlock`), `1040:0000` (line test), `HMemCpy`, `GetDC`, `ReleaseDC`, `PostMessage`.
**Yields / blocks / timing:** none (runs to completion inside the click handling).
**Edge cases:** Rows outside 0..47 end the call at once. Each of the three phases first refills the grid from the walk grid at room +0x4a (row stride 80): a cell value above `SysMapBlock` becomes -2 (free), otherwise -1 (blocked). **Phase 1 and 2 (snapping):** if the goal (then the start) cell's value is not above the variable, a breadth-first wave over the four neighbours (left, right, up, down; only cells in the inner area: not column 0 or 79, not row 0 or 47) looks for the nearest free (-2) cell and the cell becomes that one; visited cells are marked 1; the wave stops after 400 rounds (nothing is changed then, the call returns). The blocked test of the first check is a *signed* byte compare, so cell values above 127 (255 is common) count as blocked at that test, which makes the snap run (to an adjacent cell) for a start or goal on an ordinary 255 floor cell; unverified quirk. **Phase 3 (search):** wave from the start cell; each free neighbour (-2) is given its parent's cell index as a mark and queued, expanding left, right, up, down; stops when the goal is dequeued; gives up when the wave dies out. **Path:** walk back from the goal through the parent marks. A cell is stored only when the straight line (`1040:0000`) from the last stored cell to the next parent is not clear, so the list holds the goal, the corners and the start (string pulling).
