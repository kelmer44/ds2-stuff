# 1078:0454 inferred_draw_sprite
Status: understood · Cluster: graphics and sprites · Convention: cdecl far, caller cleans

**Purpose (confirmed):** Draw one sprite into the rectangle buffer being composed, clipped to its own clip rectangle (confirmed).
**Inputs:** `[bp+6..8]` scene far pointer, then the sprite far pointer, then x, y, width and height of the rectangle being composed (screen coordinates of its top-left and its size).
**Outputs / state written:** Takes the sprite's current image (sprite +0x2a), its size from the image record, and the sprite's screen top-left (+0x3e, +0x40). The first time a sprite is drawn (`+0x14` = 0) its clip rectangle (+0x16 left, +0x18 top, +0x1a right, +0x1c bottom) is set from the scene's (+0x34a left, +0x34e top, +0x34c right, +0x350 bottom) and `+0x14` becomes 1. The image is cut to the clip rectangle (cut amounts become the source x and y offsets). If the result overlaps the rectangle it calls `inferred_draw_image_rect` at the sprite's position relative to the rectangle. The keyed (transparent) flag is whether the image record's pointer at +0x14 is set, which marks images loaded as sprites.
**Calls:** `1078:1b6c`.
**Yields / blocks / timing:** none
**Edge cases:** A sprite entirely outside the rectangle is not drawn. The clip rectangle is copied only once, so later changes of the scene's clip rectangle do not reach sprites that were already drawn.
