# 1010:07c6 inferred_start_walk
Status: understood · Cluster: walking · Convention: cdecl far, caller cleans

**Purpose (confirmed):** Handle a request to walk to a screen position: convert it to grid cells and run the path search, or put the player there at once (confirmed for the conversion).
**Inputs:** Window/dc word, target x and y in screen pixels, and a flag.
**Outputs / state written:** If the flag is 0 and `DS:0054` is 0: marks the tick as busy (`DS:036e` = 1) and, when the target cell differs from the player's cell, calls `1040:011a` with the player's cell and the target cell. The target cell is column = x / 10 + 8 and row = (y - Y0) / H, with Y0 and H the two `WalkMap=` numbers (room +0xf4a, +0xf4c); the player's cell is computed from the player position `DS:3cae`, `DS:3cb0` the same way. Otherwise the player is teleported: target and position `DS:9b9a/9b98` and `DS:3cae/3cb0` are set to the target. In both cases `DS:007e` = 0x7fff and the variable `GoingOut` is set to 0.
**Calls:** `1040:011a`, `1060:0b26`.
**Yields / blocks / timing:** none
**Edge cases:** A target inside the player's own cell does not start a search. Division uses the game's signed 16-bit divide.
**Evidence:** `re/export/fn/1010_07c6.c`; callers `1048:24ee` and `1058:01e0`, `1058:0b08` (click handling).
