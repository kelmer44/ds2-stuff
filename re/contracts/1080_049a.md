# 1080:049a inferred_make_bmp_palette
Status: understood · Cluster: graphics and palette · Convention: cdecl far (dc, near pointer to a BMP colour table, selector)

**Purpose (confirmed):** Build the game's working Windows palette from the 256-entry colour table of a loaded BMP and make it current (confirmed).
**Inputs:** `[bp+6]` device context, `[bp+8]` near pointer and `[bp+a]` selector of a BMP colour table (B, G, R, unused per entry).
**Outputs / state written:** Builds a logical palette in a 0x408-byte block: entries 1 to 255 come from source entries 1 to 255 (R = src[2], G = src[1], B = src[0], flags = 1, which marks them animatable); entry 0 is forced to black with flags 0 and entry 255 is forced to white with flags 0. When the option word `DS:0062` equals 1 every colour component is first lightened to `c + ((255 - c) >> 3)`. A copy of the 256 final entries (0x400 bytes) goes to `DS:6c9e`. `CreatePalette` result replaces the handle at `DS:200a` (the old palette is selected out, then deleted), the new palette is un-realized and realized into the dc, the block is freed, and the handle is returned. Error shown if `CreatePalette` fails.
**Calls:** `LocalAlloc`, `LocalLock`, `HMemCpy`, `CreatePalette`, `SelectPalette`, `DeleteObject`, `UnrealizeObject`, `RealizePalette`, `LocalUnlock`, `LocalFree`, `1098:0000`.
**Yields / blocks / timing:** none
**Edge cases:** Source entry 0 is ignored. Black and white at the ends are the Windows system colours that a palette-managed application normally keeps.
**Evidence:** `re/export/fn/1080_049a.c` and `.asm`; called by the start-up bitmap loader `1038:0000` with the colour table of `DS2RUN.HDR` (BMP offset 0x36).
