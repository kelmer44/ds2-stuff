# 1080:0ad6 inferred_read_image_header
Status: understood · Cluster: graphics and palette · Convention: cdecl far (image record near pointer)

**Purpose (confirmed):** Fill the width, height and four extra values of an image record from its BMP header, then clear those fields in the BMP data (confirmed).
**Inputs:** `[bp+6]` near pointer to an image record whose far pointer at +2 holds the loaded BMP file.
**Outputs / state written:** Record +8 = low word of `biWidth` (BMP offset 0x12); +10 = low word of `biHeight` (0x16); +0xc, +0xe, +0x10, +0x12 = the four words at BMP offsets 0x26, 0x28, 0x2a, 0x2c (the header's pixels-per-metre fields). Those four words are then set to 0 in the BMP data.
**Calls:** stack probe only.
**Yields / blocks / timing:** none
**Edge cases:** The four words are signed 16-bit offsets and positions for sprites (see `STRUCTS.md`); the game stores them in the BMP header's pixels-per-metre fields and clears them so that Windows does not misread them. Five direct callers.
**Evidence:** `re/export/fn/1080_0ad6.c`; values checked against real files (`STRUCTS.md`).
