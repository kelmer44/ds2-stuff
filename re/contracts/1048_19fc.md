# 1048:19fc inferred_parse_entry_section
Status: understood · Cluster: script and rooms · Convention: cdecl far, caller cleans

**Purpose (confirmed):** Read the lines of an `EntryStart` .. `EntryEnd` section into a chain of 0x95-byte entry records (confirmed; the record layout is in `STRUCTS.md`).
**Inputs:** `[bp+6..8]` far pointer to the current record (the list head set up by `inferred_load_room` at room +2/+4).
**Outputs / state written:** Loops over `inferred_next_obj_token` until `ENTRYEND=` (0x1f). `COND=` allocates a new zeroed 0x95-byte record (linked at the previous record's +0x8d) and a first 0x18-byte condition node, parses the condition into it and sets the record's +0x14 to 1. `COND2=` adds another condition node (chained at node +0x14). `FROM=`: three numbers to +4, +6, +0xe. `XYROOM=`: numbers to +8, +0xa, +0xc, then a fourth to **+0xc again** (overwriting the third) and a fifth to +0x12; a missing fourth or fifth sets +0xc or +0x12 to 0. `TEXT=`: name to +0x4b, loads `NAME.txt` into memory (pointer at +0x16/+0x18, cut at the first CR). `EFFECT=` name to +0x3e, `SPEECH=` name to +0x4b, `PICTURE=` name to +0x31, `DIALOG=` name to +0x58, `DESTROY=` sets +0x10 = 1, `PALETTECHANGE=` a number to +0x14, `ANIM=` four numbers to +0x27, +0x29, +0x2b, +0x2d, a name to +0x1a and a fifth number to +0x2f, `CHANGE=` assignment list to +0x79, `CHANGEAT=` assignment list to +0x65, `WAITUNTIL=` starts a new record (chained at +0x8d) whose condition node is parsed from the line. Other keys are ignored.
**Calls:** `1048:0000`, `1060:0652` (terms), `1060:0c44` (numbers), `1060:0188` (word), `1060:0062` (identifier), `1098:0326`, `1090:0000`, `lstrcpy`, `lstrcat`.
**Yields / blocks / timing:** none
**Edge cases:** The overwrite of +0xc by the fourth `XYROOM=` number is read directly from the assembly (the destination pointer saved at `1048:1b80` is pushed again at `1048:1ba3`); the object-action parser `1048:042c` uses five distinct destinations, so this may be an original defect or an intended reuse. The text file name is built as `NAME` + `.txt`. Names are copied without length checks into 13-byte fields.
