# 1020:0656 inferred_scale_image
Status: understood · Cluster: graphics and sprites · Convention: cdecl far, caller cleans

**Purpose (confirmed):** Make a scaled (and optionally mirrored) copy of an image record as a new, uncompressed 8-bit picture, with its placement offsets scaled too.
**Inputs:** `[bp+6]` device context (not used), `[bp+8]` source image record near pointer with `[bp+a]` its selector (the source's file data is at record +2/+4), then the destination image record far pointer (offset, selector), a scale value in 1/128 units (128 = 100%), and a mode word 0 to 3.
**Outputs / state written:** With no source: the destination's data pointer (+2/+4) is cleared. Otherwise: new width = `srcWidth * scale / 128`, new height = `srcHeight * scale / 128` (16-bit product), both forced to 5 when either is below 5. Destination record: +8 width, +10 height, +0xc = `srcOffsetX * scale / 128` (for modes 2 and 3, which mirror: `-((srcWidth + srcOffsetX) * scale / 128)`), +0xe = `srcOffsetY * scale / 128`. A new block of `(newWidth + 16) * newHeight + bfOffBits` bytes is allocated, the source's file header and colour table (`bfOffBits` bytes) are copied into it, the new header gets biWidth = the row stride `((newWidth - 1) & ~3) + 4`, biHeight = new height, biCompression = 0 and file size = block size, and the pixels are produced by `10c0:0000` (the stretch routine) with the mode mapped 0 to 0, 1 to 2, 2 to 1, 3 to 3.
**Calls:** `10d0:052a` (32-bit multiply), `10d0:0490` (32-bit divide), `1090:0000`, `10c0:0000`.
**Yields / blocks / timing:** none
**Edge cases:** Integer division truncates toward zero. The minimum size is 5 x 5 whatever the scale; very small scales still draw a 5 x 5 picture. The previous pixel block of the destination is not freed here (the caller frees it first). Mode values above 3 return without drawing and leave a half-built record.
**Evidence:** `re/export/fn/1020_0656.c`; the only caller is `1038:01e4`, which passes the scale of the object.

**Validation:** none yet
**Open questions:** how the stretch routine rounds source pixels (nearest neighbour with fixed-point steps is expected, the exact rule is in `10c8:0100`, unread); what modes 1 and 2 do in the stretch routine (flip vertically or both).
